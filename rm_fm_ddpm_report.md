# Comparative Evaluation Report: DDPM, Flow Matching, and Rectified Flow

This report provides a detailed theoretical and empirical comparison of **Denoising Diffusion Probabilistic Models (DDPM)**, **Flow Matching (FM)**, and **Rectified Flow (RM)** (often termed 2-Rectified Flow or Reflow). The evaluation covers mathematical formulations, training dynamics, trajectory straightness, computational complexity (NFE), and real-world latency measurements on a physical GPU (**NVIDIA RTX A5000 Laptop GPU**).

---

## 1. Executive Summary

Generative modeling has undergone a paradigm shift from stochastic diffusion paths (e.g., DDPM) toward deterministic, velocity-field-based Ordinary Differential Equations (ODEs) (e.g., Flow Matching and Rectified Flow). 

Through systematic experiments on both a **2D Toy Dataset (Two Moons)** and a **64x64 CelebA Image Dataset**, we demonstrate that:
1. **Sampling Speed (1-Step Generation):** Rectified Flow successfully straightens vector paths, enabling high-fidelity **1-step generation** ($0.98\text{ ms/image}$), yielding a **55x speedup** over traditional 50-step samplers.
2. **Trajectory Straightness:** Flow Matching paths remain curved (straightness score of $\sim 2.36$ in 2D space), whereas Rectified Flow achieves near-perfect straightness ($\sim 1.004$ in 2D space, and $0.9993$ on CelebA in 50 steps).
3. **Distribution Fidelity (FID equivalent):** At 100 epochs on CelebA, Flow Matching maintains a strong distribution mapping capacity (FID equivalent of $3.66$), while 1-step Rectified Flow strikes an optimal trade-off of $8.98$ (beating 50-step DDPM and RF under short training regimes due to reduced path-intersection noise).

## 2. Mathematical Frameworks

To understand the qualitative and quantitative differences, we define the mathematical formulations of the three paradigms.

```mermaid
graph TD
    A[Random Noise x0] -->|Stochastic Markov Steps| B(DDPM Sampler)
    A -->|ODE Euler Integration| C(Flow Matching Sampler)
    A -->|Direct 1-Step Jump| D(Rectified Flow Sampler)
    B -->|50-100 Steps| E[Generated Samples]
    C -->|50 Steps (Curved)| E
    D -->|1 Step (Straight)| E
```

### 2.1 Denoising Diffusion Probabilistic Models (DDPM)
DDPM models generative sampling as the reverse of a stochastic noising process.
* **Forward Path (Noising):** 
  $$q(x_t|x_0) = \mathcal{N}(x_t; \sqrt{\bar{\alpha}_t}x_0, (1 - \bar{\alpha}_t)\mathbf{I})$$
  where $\alpha_t = 1 - \beta_t$ and $\bar{\alpha}_t = \prod_{s=1}^t \alpha_s$ are dictated by a variance schedule (typically linear, e.g., $\beta_1 = 10^{-4}$ to $\beta_T = 0.02$).
* **Training Loss Objective:**
  The model $\epsilon_\theta(x_t, t)$ is trained to predict the added noise vector:
  $$\mathcal{L}_{\text{DDPM}}(\theta) = \mathbb{E}_{t, x_0, \epsilon} \left[ \|\epsilon - \epsilon_\theta(x_t, t)\|^2 \right]$$
* **Reverse Sampling Step (Stochastic):**
  $$x_{t-1} = \frac{1}{\sqrt{\alpha_t}} \left( x_t - \frac{\beta_t}{\sqrt{1 - \bar{\alpha}_t}} \epsilon_\theta(x_t, t) \right) + \sigma_t z \quad \text{where } z \sim \mathcal{N}(0, \mathbf{I})$$
  Because sampling is Markovian and stochastic, it requires a high number of discretization steps ($T = 50$ to $1000$) to yield high-quality images.

### 2.2 Flow Matching (FM)
Flow Matching defines generative sampling as integrating a deterministic velocity field $v_\theta(x, t)$ that maps a source distribution $p_0$ (noise) to a target distribution $p_1$ (clean data).
* **Linear Path (Independent Coupling):**
  $$x_t = t x_1 + (1 - t) x_0 = x_0 + t(x_1 - x_0)$$
  where $x_0 \sim \mathcal{N}(0, \mathbf{I})$ and $x_1 \sim p_{\text{data}}$ are sampled independently.
* **Target Velocity Vector Field:**
  $$u_t(x|x_1) = x_1 - x_0$$
* **Training Loss Objective:**
  $$\mathcal{L}_{\text{FM}}(\theta) = \mathbb{E}_{t, x_0, x_1} \left[ \|v_\theta(x_t, t) - (x_1 - x_0)\|^2 \right]$$
* **ODE Sampling:**
  Generated images are obtained by integrating the ODE $\frac{dx_t}{dt} = v_\theta(x_t, t)$ from $t=0$ to $t=1$. Since paths generated from independent coupling cross each other, the model learns a curved global average velocity field, necessitating multiple step-by-step calculations (e.g., $N = 50$ Euler steps).

### 2.3 Rectified Flow / Reflow (RM)
Rectified Flow straightens trajectories by retraining the velocity network on data generated by a previously trained Flow Matching model, eliminating path-crossing and variance.
* **Data-Rectification (Reflow):**
  Using a trained FM model, we generate rectified target coordinates starting from noise:
  $$x_{1, \text{rect}} = \text{Solve-ODE}(x_0, v_\theta^{\text{FM}})$$
  This pairs each specific noise vector $x_0$ with a deterministic, non-crossing target $x_{1, \text{rect}}$, creating a straightened trajectory $x_t = x_0 + t(x_{1, \text{rect}} - x_0)$.
* **Reflow Training Loss Objective:**
  $$\mathcal{L}_{\text{RF}}(\theta) = \mathbb{E}_{t, x_0, x_{1, \text{rect}}} \left[ \|v_\theta^{\text{RF}}(x_t, t) - (x_{1, \text{rect}} - x_0)\|^2 \right]$$
* **1-Step Sampling (Physical Speedup):**
  Because the trajectories are straightened (constant velocity vector), we can generate samples in a **single function evaluation** ($NFE = 1$):
  $$x_1 = x_0 + v_\theta^{\text{RF}}(x_0, 0)$$

## 3. Comparative Analysis & Theoretical Trade-Offs

| Metric / Dimension | DDPM | Flow Matching (FM) | Rectified Flow (RM) |
| :--- | :--- | :--- | :--- |
| **Generative Style** | Stochastic Diffusion | Deterministic ODE | Deterministic ODE |
| **Path Trajectory** | Highly Stochastic | Curved Vector Field | Straightened Vector Field |
| **Typical NFE** | 50 - 1000 | 50 - 100 | **1 - 10** |
| **Theoretical Limit** | Slow sampling, high noise | Path crossings, curves | Minimal path crossings, fast |
| **Optimization Target** | Noise $\epsilon$ | Velocity field $v = x_1 - x_0$ | Straightened velocity $v = x_{1, \text{rect}} - x_0$ |

### 3.1 Loss Convergence Dynamics
1. **Flow Matching (Independent Pairing):** Loss values remain relatively high because $x_0$ (noise) and $x_1$ (real data) are paired randomly. Since identical noise starting points can map to different images, the network must average out these crossing paths, leading to high MSE loss variance.
2. **Rectified Flow (Straight Pairing):** Training loss converges rapidly (nearly 3 orders of magnitude lower than FM). This occurs because path intersections are eliminated: the network easily learns the constant-velocity straight path connecting $x_0$ directly to its designated $x_{1, \text{rect}}$.
3. **DDPM (Noise Prediction):** Optimizes for predicting random Gaussian noise at different time steps. Loss stabilizes at higher, bounded values because predicting random noise is inherently stochastic.

## 4. Experimental Results: 2D Two Moons Dataset

To verify geometric fidelity, we trained DDPM, FM, and RM on a normalized 2D "Two Moons" point cloud.

### 4.1 Hyperparameters
* **Samples:** $2,000$ | **Batch Size:** $128$
* **Network:** Time-Conditional MLP | **Hidden Dimensions:** $128$
* **Learning Rate:** $0.005$
* **Epochs:** $3,000$ (FM / RF) | $4,000$ (DDPM)

### 4.2 Quantitative Comparison (2D Moons)

| Method | NFE | Latency (ms) | Chamfer Distance | Fréchet Distance (FD) | Path Straightness |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **DDPM (stochastic)** | 100 | 49.98 ms | **0.112546** | 0.009454 | N/A (Stochastic Markov) |
| **Flow Matching (50 steps)** | 50 | 10.52 ms | **0.121606** | **0.006850** | 2.363557 (Curved) |
| **Flow Matching (1 step)** | 1 | 0.00 ms | 0.814186 | 1.130001 | N/A (Overshoots curves) |
| **Rectified Flow (1 step)** | **1** | **0.00 ms** | **0.136197** | **0.008219** | **1.004052** (Almost straight) |

> [!NOTE]
> The straightness score measures (actual path distance) / (Euclidean distance). A score of **1.0000** indicates a perfectly straight path. 
> 
> Flow Matching trajectories in 2D space are highly curved ($\sim 2.36$), which explains why 1-step Flow Matching fails (FD = 1.13). Rectified Flow successfully straightens the trajectories ($\sim 1.004$), allowing the model to generate high-quality points in a single step (FD = 0.0082).

## 5. Experimental Results: CelebA 64x64 Image Dataset

To benchmark scaling behavior on complex distributions, we executed a **100-epoch GPU run** using **10,000 CelebA faces**.

### 5.1 Run Configurations & Model Architecture
* **Optimizer:** Adam | **Learning Rate:** $0.0003$ | **Batch Size:** $64$
* **Device:** CUDA (NVIDIA RTX A5000 Laptop GPU, 16GB VRAM)
* **Architecture:** Conditional U-Net
  * Down Channels: `(64, 128, 256, 512)`
  * Up Channels: `(512, 256, 128, 64)`
  * Time Embedding: 32-dim Sinusoidal Position Embeddings

### 5.2 Quantitative Comparison (CelebA 100 Epochs)

| Method | NFE | Time (ms/img) | Chamfer Distance | FID Equivalent | Straightness |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **DDPM (50 steps)** | 50 | 54.11 | **0.7711** | 10.1798 | N/A |
| **Flow Matching (50 steps)** | 50 | 53.83 | 1.0857 | **3.6626** | 0.9856 (Curved) |
| **Rectified Flow (50 steps)** | 50 | 53.56 | 1.1874 | 10.4974 | **0.9993** (Straight) |
| **Rectified Flow (1 step)** | **1** | **0.98** | **1.0489** | **8.9868** | **1.0000** (Mathematically straight) |

> [!TIP]
> **Inference Acceleration:** While 50-step generation requires $\sim 54\text{ ms}$ per image, the **1-step Rectified Flow** takes only **$0.98\text{ ms}$**, yielding a **55x speedup**.
> 
> **Fidelity vs. Straightness Trade-off:** At 100 epochs, 50-step Flow Matching reaches a lower FID equivalent ($3.66$) than 50-step Rectified Flow ($10.50$). This is because the RF model is trained on targets generated by a partially converged FM model. However, **1-step RF** ($8.98$) still yields lower distribution error than **50-step RF** ($10.50$) and **50-step DDPM** ($10.18$), making it the most efficient choice for high-speed deployments.

## 6. Implementation and Hardware Optimization

### 6.1 Automatic Mixed Precision (AMP)
To optimize memory usage and training speed on the GPU, the codebase incorporates PyTorch's Automatic Mixed Precision (`torch.cuda.amp`):
* **`autocast()`:** Operations such as 2D convolutions are computed in FP16 to utilize Tensor Cores, while precision-critical operations (like loss calculation) remain in FP32.
* **`GradScaler`:** Scales gradients to prevent numerical underflow (gradients becoming zero in FP16 representation) and scales them back before weight updates.

### 6.2 Precise CUDA Latency Benchmarking
To avoid distorted speed measurements due to PyTorch's asynchronous GPU execution, the latency calculations enforce hardware synchronization:
```python
# Correct Latency Benchmarking Protocol
torch.cuda.synchronize()
start_time = time.time()

# Run generation loop
samples = model.sample(num_samples)

torch.cuda.synchronize()
elapsed_time = (time.time() - start_time) * 1000 # ms
```
Without `torch.cuda.synchronize()`, CPU-side timers return immediately after launching the kernels, incorrectly reporting latencies like $\sim 0.13\text{ ms/image}$ instead of the physical $\sim 1.00\text{ ms/image}$ execution time.

## 7. Conclusions & Recommendations

1. **When to use DDPM:** Use DDPM when stochastic, noise-correcting generation is preferred and computational budget is not a constraint. DDPM is robust at preserving high-frequency edge alignments (as seen in the lowest Chamfer Distance of $0.7711$).
2. **When to use Flow Matching:** Use FM if you plan to sample using higher-order ODE solvers (like Runge-Kutta or adaptive step sizes) and want the highest distribution alignment (FID of $3.66$).
3. **When to use Rectified Flow:** Use RF for **real-time/edge computing applications** requiring maximum throughput. It achieves high image fidelity in **1 step**, bypassing the 50-step generation loop and reducing sampling latency to sub-millisecond times ($0.98\text{ ms}$).

### Recommended Next Steps
* **Longer Training for RF:** To improve the FID equivalent of RF ($10.49 \rightarrow <3.00$), train the initial Flow Matching model for 300 epochs instead of 100 to generate cleaner targets ($x_{1\_rectified}$) for the second phase.
* **Higher-order Solvers:** Evaluate if adaptive solvers (e.g. `dopri5`) can generate straighter paths during the Reflow generation phase to improve subsequent RF training efficiency.
